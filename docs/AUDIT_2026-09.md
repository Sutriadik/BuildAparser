## 2. Bug yang ditemukan & diperbaiki

| # | Bug | Dampak | Perbaikan |
|---|---|---|---|
| 1 | Ollama dipanggil tanpa `num_ctx` | Default server ±4096 token; prompt kontrak ±8k token → **awal prompt (system prompt) terpotong diam-diam** → hasil tidak konsisten | `OLLAMA_NUM_CTX=12288`, `seed`, temperature 0, peringatan bila prompt mendekati batas |
| 2 | Bounding box Docling terbalik vertikal | Semua highlight evidence Docling menunjuk lokasi cerminan (header tercatat di ymin 0.89, LandingAI 0.08) | Konversi ke origin kiri-atas (`to_top_left_origin`) |
| 3 | Grounding: teks yang memuat satu angka diperlakukan sebagai angka | Alamat "Jl. … No. 1" ter-ground ke "1. LINGKUP PEKERJAAN" dengan confidence 0.97 | Matcher baru: angka dicocokkan per token yang di-parse; angka kecil tidak di-ground ke teks acak |
| 4 | Grounding: `str(157500000.0)` = `"157500000.0"` | Nominal harga hampir tidak pernah ter-ground | `format_number_for_matching` + parsing format Indonesia |
| 5 | Few-shot prompt memakai nilai asli SPK ATS Oracle & SPH Bapenda | Dokumen uji = contoh prompt → **akurasi baseline palsu tinggi**; LLM menyalin nilai contoh ke dokumen lain | Contoh diganti data fiktif, aturan anti-halusinasi, test yang mencegah kebocoran |
| 6 | Normalisasi angka tanpa batas kata | NPWP `01.234.567.8-901.000` → `01234567.8-901.000` sebelum masuk LLM | Regex dengan guard; satu modul `deterministic/numbers.py` |
| 7 | Text cleaner `,(\S)` dan split CamelCase | `174.825.000,00` → `174.825.000, 00`; `1,5` → `1, 5`; `FortiGate` → `Forti Gate` | Koma setelah digit tidak disentuh; split kata hanya jika kata kiri ≥ 6 huruf |
| 8 | Deteksi kolom tabel via substring | SPK: `volume = 157.500.000` (kolom "Jumlah Harga"), `unit = "157.500.000"` (kolom "Harga Satuan"); tabel non-harga ikut jadi item | Pencocokan header per kata + exclude kata harga; tabel tanpa kolom harga dilewati |
| 9 | Hint regex ([KEY: …]) yang disisipkan ke prompt | "No. 1" alamat → No. Rekening, "a.n PT" → Nama Rekening "PT", tanggal akta 1991 → Tanggal Dokumen | Pola bank hanya di sekitar "rekening", tanggal dokumen hanya setelah "Dibuat di", satu kandidat per field |
| 10 | Rekonsiliasi item: tabel menggantikan item LLM jika jumlah baris ≥ | Tabel yang salah bisa menimpa item LLM yang benar | Pilih sumber berdasarkan kecocokan jumlah dengan subtotal/total |
| 11 | Terbilang tidak divalidasi | LLM menghilangkan "Ribu" (174.825.000 → 174.000.825) dan tetap diterima | Validator terbilang + koreksi deterministik dari kalimat terbilang di dokumen |
| 12 | Docling selalu `do_ocr=True` | PDF digital tetap memuat model OCR & OCR semua gambar | Profiler per halaman (PyMuPDF, 1–140 ms) → OCR hanya bila perlu |
| 13 | Semua model di-import saat startup API | Import ±4.9 s + memuat model sebelum ada request | Lazy import; `import app.main` 0.3 s |
| 14 | API: `file.filename` dipakai sebagai path, endpoint `async` memanggil kode blocking | Path traversal & tabrakan nama upload; event loop terblokir selama pemrosesan (menit-an) | Nama file aman di folder unik, endpoint `def` (threadpool), lock engine, `reload` hanya via env |
| 15 | Classifier "first match" substring | SPH yang menyebut "SPK" terklasifikasi kontrak | Skor berbobot dengan batas kata & bobot judul |
| 16 | `quality_report.grounding_rate` beda penyebut (list dihitung 1, grounding per elemen) | Rate bisa > 100% | Dihitung dari evidence per field |

**Satu-satunya field yang masih kosong (Tanggal Negosiasi) adalah masalah OCR, bukan ekstraksi.**
Docling OCR merusak kalimatnya menjadi "Ber aal ana ea a a al a aan …". Uji cepat PaddleOCR (PP-Structure)
membaca kalimat itu dengan benar, tetapi hanya menghasilkan 1.355 karakter (Docling 4.627) dan tabel harga
halaman 3 terbaca sebagai gambar. Kesimpulan: engine OCR harus dipilih lewat benchmark per field
(Plan Phase 7), bukan dengan mengganti engine secara global.

## 6. Langkah berikutnya (urut prioritas)

1. **Golden dataset**: tambah minimal 5 kontrak + 5 SPH (native & scan). Tanpa ini semua angka akurasi masih anekdot.
2. **Benchmark OCR** di dataset yang sama: Docling OCR vs PaddleOCR vs (nanti) dots.mocr — ukur akurasi field, bukan kesan visual.
3. **LLM mengembalikan `evidence_quote` per field** (Plan §13) supaya evidence dicari dari kutipan, bukan dari nilai.
4. **Cross-document reconciliation** Kontrak ↔ SPH (produk, qty, harga, total).
5. **Kalibrasi bobot confidence** (`app/evidence/locator.py`) dari golden dataset.
6. Pisahkan dependency OCR/dev (`requirements-ocr.txt`, `requirements-dev.txt`).
